# 已知问题

## P0/P1 级问题

1. 真实 metric JSON/CSV 不在本地仓库，资产生成曾全部使用 fallback。
2. 旧版脚本使用 `/root/autodl-tmp/...` 绝对路径，不适合本地复现；当前已改为显式参数配置，但真实路径仍需人工提供。

4. 当前 validation log 是来源审计日志，不是原始 nnU-Net 验证日志；不能仅凭它证明真实 JSON 已读取。

## 结果和图表问题

- PNG 已做可读性快速检查，但仍需在目标期刊尺寸、灰度打印和字体嵌入要求下人工复核。
- 误差线代表当前记录中的区域 Dice 标准差；Mean 没有单独标准差记录。
- 当前结果没有病例级分布、HD95、置信区间和统计检验。

## 仓库卫生问题

- `run_debug.log` 和 `validation_log.txt` 是历史生成日志，当前扫描未发现 token、密码或患者图像，但日志对 GitHub 不是必要的；后续可考虑 `git rm --cached` 后仅在本地保留。
- 结果目录中的 PNG、CSV、XLSX 体量都较小，没有发现超过 10 MB 的文件。
- 仓库没有跟踪 `nii.gz`、`pth`、`pt`、`ckpt`、数据目录或密钥文件。

## 不应直接解决的问题

- 不要猜测或硬编码远程服务器目录。
- 不要为了让图表变得“自动化”而把 fallback 静默替换成未知来源数值。
- 不要把当前 baseline 结果写成最终方法、临床验证或统计显著结论。
